# ТЗ: Android-приложение для локального управления Wi-Fi IP-камерой (Xiongmai/LiteOS, DVRIP)

**Версия:** 1.0 · **Тип:** личный инструмент · **Платформа:** Android (нативно, Kotlin) ·
**Назначение:** полностью локальное управление ОДНОЙ конкретной моделью камеры без китайского облака и без стороннего приложения.

Документ самодостаточен: раздел **§9 (Протокол)** содержит всё, что нужно для реализации сетевой части «с нуля».

---

## 1. Контекст и цель

Есть дешёвая китайская батарейная Wi-Fi PIR-камера на Xiongmai (SoC HiSilicon Hi3518EV200, прошивка Huawei LiteOS).
Штатное приложение — китайское, некупированное, гонит трафик в облако (`secu100.net`, `push.umeye.cn`).
Нужно **своё нативное Android-приложение**, которое по локальному протоколу **DVRIP** (TCP 34567) делает:
- находит камеру в сети,
- показывает живое видео + звук (реалтайм),
- показывает и проигрывает архив с SD-карты (с перемоткой),
- настраивает камеру,
- поддерживает **несколько экземпляров этой же камеры**.

Приложение личное: без Play-Store-хардненинга, но должно быть надёжным и корректно обрабатывать сон камеры.

## 2. Целевое устройство (жёстко под него)

| Параметр | Значение |
|---|---|
| SoC | HiSilicon Hi3518EV200 |
| Прошивка | LiteOS (`V1.01.LITEOS.A6434532...`) |
| Видео | H.264, Main **1080p**, Extra **D1**; аудио **G.711 A-law (PCMA) 8 кГц** |
| Протокол | **DVRIP/Sofia**, TCP **34567** (единственный рабочий канал управления и видео) |
| RTSP/ONVIF | **ОТСУТСТВУЮТ** — забыть про них, видео только через DVRIP OPMonitor |
| Снапшот `OPSNAP` | не реализован — кадр берём из потока |
| Веб :80 | стоковый OCX (для приложения бесполезен) |
| Питание | батарея + USB-зарядка |
| Датчик | PIR (движение) + human-detect |
| Накопитель | microSD, путь `/mnt/sd0` |
| Discovery | камера сама шлёт UDP-broadcast на порт **34569** (JSON с NetCommon) |
| Логин | `admin`, пароль задаётся пользователем; хэш — **sofia_hash** (см. §9.2) |

**Поведение сна (ВАЖНО для UX):** камера батарейная и **засыпает** через ~30–90 с простоя.
- Лёгкий сон: RPS-канал к облаку жив, но локально DVRIP не отвечает.
- Глубокий сон: **полностью уходит из сети** (не пингуется, DVRIP `timeout`).
- **Разбудить по сети НЕЛЬЗЯ** (проверено: ни DVRIP-коннект, ни Wake-on-LAN). Будят только: **движение перед камерой (PIR)**, внешнее питание, или облачный пуш из штатного приложения.
- Пока идёт активный поток (OPMonitor) — камера **не засыпает**. На это и опираемся (см. §3).

## 3. Модель работы «побудка движением + удержание» (ключевое требование)

Приложение **не пытается** будить камеру по сети (это невозможно). Вместо этого:

1. Пользователь хочет посмотреть → приложение показывает экран Live со статусом **«Камера спит — помашите рукой перед ней, чтобы разбудить»** и в фоне **опрашивает** доступность (TCP-connect на 34567 раз в ~1–2 с).
2. Пользователь провоцирует движение (PIR) → камера просыпается → приложение **мгновенно ловит момент доступности**, логинится и запускает **OPMonitor-поток**.
3. Пока пользователь смотрит — приложение **держит поток открытым** (это не даёт камере заснуть) → реалтайм-просмотр.
4. Пользователь закрыл Live → поток закрывается → камера сама уходит в обычный режим/сон.

**В обычном состоянии приложение НЕ меняет работу камеры**: не отключает облако, не трогает PIR/сон/расписание. Все «инвазивные» настройки (напр. отвязка от облака) — только явным действием пользователя в настройках, по умолчанию выключены.

## 4. Область (scope) и НЕ-scope

**В scope:**
- Только **эта модель** камеры (Hi3518EV200/LiteOS/DVRIP/H.264). Квирки можно хардкодить.
- **Несколько экземпляров** этой же камеры (список, переключение, мультивью опционально).
- Работа только в **локальной сети (LAN)**.

**Вне scope (v1):**
- Удалённый доступ вне дома (VPN/облако) — заложить архитектурно, но не делать.
- Пуш-уведомления о движении в фоне (камера шлёт события в облако; без домашнего сервера телефон их локально ловить не может — не делаем).
- Поддержка других моделей/H.265/RTSP-камер.
- Перепрошивка.

## 5. Функциональные требования (по экранам)

### 5.1 Экран «Мои камеры» (список / дашборд)
- Список добавленных камер: имя, превью-иконка/последний кадр, статус (● в сети / ○ спит), IP.
- Действия: добавить камеру, открыть камеру, редактировать, удалить, переупорядочить.
- Хранение списка локально (Room). Креды — в Android Keystore (см. §7).
- Статус каждой камеры обновляется лёгким TCP-probe (не будит камеру).

### 5.2 Добавление / поиск камеры
- **Автопоиск (Discovery):** слушать UDP-broadcast на **34569** + отправлять активный probe (см. §9.9); показать найденные камеры (IP, MAC, имя). Тап → добавить.
- **По IP вручную:** ввод IP (порт 34567 по умолчанию), логин `admin` + пароль.
- **Проверка соединения** при добавлении: login → `Ret:100` = успех; показать модель/серийник из `SystemInfo`.
- **Рекомендация в UI:** предложить закрепить статический DHCP-lease на роутере (IP камеры может меняться) — просто текстовая подсказка.

### 5.3 Онбординг новой/сброшенной камеры (Wi-Fi setup)
Два метода (BLE НЕ поддерживается этой камерой):
- **A. QR-код** (рекомендуемый): приложение генерирует QR со строкой (формат §9.10), пользователь показывает его объективу камеры **в режиме сетапа** (после factory reset, камера голосом «quick setup»). Камера читает QR и заходит в сеть.
- **B. SoftAP:** камера после сброса поднимает точку `xmTEXT` (или `camera_XXXX`); приложение просит пользователя подключить телефон к этой точке, затем по DVRIP (камера на `192.168.1.10/.12`, порт 34567) шлёт `SET NetWork.Wifi` (§9.8). Требует, чтобы Android дал приложению работать с этой Wi-Fi без интернета.
- Мастер-шаги с картинками/подсказками; напомнить: **QR читается только в режиме сетапа**, окно AP короткое (батарея) — держать камеру на USB-питании.
- Смена Wi-Fi на **уже подключённой** камере — просто `SET NetWork.Wifi` (без reset/QR).

### 5.4 Экран Live (живое видео)
- Реализация модели §3 (ожидание пробуждения → захват потока → удержание).
- Видео: **DVRIP OPMonitor** (§9.5), декод **нативно через MediaCodec** (H.264). Аудио G.711 A-law → декод в PCM → воспроизведение.
- Элементы: переключатель **Main/Extra**, кнопка **снапшот** (сохранить текущий кадр в галерею), кнопка **запись** (писать поток в mp4 на телефон), **двусторонний звук** (push-to-talk, §9.7), индикатор битрейта/fps, статус сна.
- Full-screen, поворот (камера может быть смонтирована боком — дать поворот картинки в UI).
- Автопереподключение при обрыве; при засыпании — вернуть в состояние «ожидание пробуждения».

### 5.5 Экран Архив (SD-карта)
- Список записей: `OPFileQuery` (§9.6) с пагинацией по времени (лимит ~64/запрос).
- Навигация по **датам/календарю**. ⚠️ Учесть, что часть записей имеет **неверный год** (2023/2024/2025) из-за несинхронизированных часов камеры при съёмке — показывать как есть, группировать по фактической дате из имени файла.
- Фильтр: `[A]` = движение (PIR), `[R]` = обычная запись.
- Тап по записи → **потоковое проигрывание** (§9.6: Claim 1424 → DownloadStart 1420, данные 1426, до EOF; демукс как в live; декод MediaCodec). Старт быстрый (проигрывать по мере скачивания), с **перемоткой** (буфер обгоняет, т.к. скачивание ~5 Мбит/с > битрейта видео).
- Скачивание записи в mp4 на телефон + шаринг. Превью-кадры (первый I-frame). Кеш скачанных.
- Инфо о карте: если доступно — статус/объём (`Storage`, `StorageInfo`); формат карты — опционально, с подтверждением (деструктивно).

### 5.6 Экран Настройки камеры (config get/set, §9.4)
Дружелюбные контролы (переключатели/списки/слайдеры), не сырой JSON:
- **Сеть/Wi-Fi:** сменить сеть (`NetWork.Wifi`), IP-инфо (`NetWork.NetCommon`), NTP (`NetWork.NetNTP`).
- **Видео/кодек** (`Simplify.Encode`): разрешение, FPS, битрейт, GOP для Main/Extra.
- **OSD** (`AVEnc.VideoWidget`): имя канала, показ времени, **приватные маски** (до 4 зон, координаты 0–8192).
- **Изображение** (`Camera.Param`/`ParamEx`): день/ночь, флип/зеркало, WDR, шумодав.
- **Детекция движения** (`Detect.MotionDetect`): вкл/выкл, чувствительность, зоны (сетка), расписание, действия (снап/запись).
- **PIR** (`Alarm.PIR`): чувствительность, расписание, действия.
- **Запись** (`Record`): расписание (недельная сетка off/continuous/motion), преролл, длина файла.
- **Время:** показать (`OPTimeQuery` 1452), синхронизировать с телефоном (`OPTimeSetting` 1450).
- **Аккаунт:** сменить пароль (`ChangeRandomUser` 1660), восстановить пароль из серийника (`GetRandomUser` 1660, §9.11).
- **Приватность (по умолчанию ВЫКЛ, отдельным разделом с предупреждением):** «Отвязать от облака» → `SET NetWork.Nat NatEnable=false` + `SET NetWork.PMS Enable=false`. Обратимо. Не трогать без явного действия пользователя (см. §3 п.«обычная работа»).

### 5.7 Общий UX
- Тёмная тема, Jetpack Compose, one-hand-friendly.
- Везде честный статус камеры (в сети/спит) и понятные подсказки про пробуждение движением.
- Никаких упоминаний/зависимостей от облака.

## 6. Нефункциональные требования
- **Нативно:** Kotlin + Jetpack Compose. Сетевой стек DVRIP — **свой** (сокеты/корутины), без сторонних бриджей (go2rtc/ffmpeg не тянуть; декод — системный `MediaCodec`).
- **Мин. Android:** 8.0 (API 26).
- **Многопоточность:** корутины; каждая камера — свой набор соединений; тяжёлые операции (поток/скачивание) сериализовать per-camera (на камере `TCPMaxConn=10`, но чтение с SD ~5 Мбит/с — одно тяжёлое за раз).
- **Надёжность:** таймауты, авто-reconnect с backoff, keepalive (opcode 1006). Корректная обработка «камера уснула посреди операции».
- **Производительность:** видео декодить аппаратно (MediaCodec surface), не блокировать UI-поток.
- **Хранение:** список камер — Room; креды/пароли — **EncryptedSharedPreferences/Keystore**; кеш записей/превью — внутреннее хранилище.
- **Локализация:** RU (основной), строки вынести в ресурсы.

## 7. Безопасность/креды

## 9. ПРОТОКОЛ DVRIP — полное описание для реализации

> Всё ниже проверено на реальной камере. Порядок байт — **little-endian**.

### 9.1 Формат сообщения
Каждое сообщение = **20-байтный заголовок + тело**. Тело — UTF-8 JSON, завершается байтами `0x0A 0x00`.

Заголовок (20 байт), поля по смещениям:
| Смещение | Тип | Значение |
|---|---|---|
| 0 | u8 | `0xFF` (флаг начала) |
| 1 | u8 | `0x00` (версия) |
| 2 | u16 | `0x0000` (reserved) |
| 4 | u32 LE | **SessionID** (число; 0 до логина) |
| 8 | u32 LE | **Sequence** (счётчик запроса) |
| 12 | u8 | `0x00` (total packets) |
| 13 | u8 | `0x00` (current packet) |
| 14 | u16 LE | **MsgID** (опкод) |
| 16 | u32 LE | **длина тела** (байт) |

Упаковка (референс на Python): `struct.pack("<BBHIIBBHI", 0xff,0,0, session, seq, 0,0, msgid, len(body)) + body`.
Разбор ответа: прочитать 20 байт, взять `MsgID = u16@14`, `len = u32@16`, затем прочитать `len` байт тела; JSON до первого `\x00`.

### 9.2 sofia_hash (хэш пароля)
```
md5 = MD5(password_utf8)            // 16 байт
ALPHABET = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz" // 62 симв
hash = ""
for i in 0..7:
    hash += ALPHABET[(md5[2*i] + md5[2*i+1]) % 62]
// результат — строка из 8 символов
```

### 9.3 Логин
- MsgID **1000**, тело: `{"EncryptType":"MD5","LoginType":"DVRIP-Web","UserName":"admin","PassWord":"<sofia_hash>"}`.
- Ответ: `{"Ret":100,"SessionID":"0x00000001",...}`. `Ret:100`=OK, `106`=неверный пароль.
- Далее **SessionID** класть в заголовок (как число) и в тело каждого запроса как строку `"SessionID":"0x...."`.
- **Keepalive:** MsgID **1006** периодически (`{"Name":"KeepAlive","SessionID":"0x..."}`), чтобы держать сессию.

### 9.4 Чтение/запись конфига
- **GET:** MsgID **1042**, тело `{"Name":"<Секция>","SessionID":"0x..."}`. Ответ: `{"Name":"<Секция>","<Секция>":<value>,"Ret":100,"SessionID":...}`.
- **SET:** MsgID **1040**, тело `{"Name":"<Секция>","SessionID":"0x...","<Секция>":<value>}`. Ответ `Ret:100`.
- **Ability (возможности):** MsgID **1360**, тело `{"Name":"<Ability>","SessionID":...}`.
- Коды: `100`=OK, `102`=секция не поддержана, `103`=команда не поддержана.

**Ключевые секции и структуры (реальные значения-образцы):**

`Simplify.Encode` (массив из 1 канала):
```json
[{"MainFormat":{"Video":{"Compression":"H.264","Resolution":"1080P","FPS":25,"BitRate":2048,
   "BitRateControl":"VBR","GOP":2,"Quality":4},"AudioEnable":true,"VideoEnable":true},
  "ExtraFormat":{"Video":{"Compression":"H.264","Resolution":"D1","FPS":20,"BitRate":384,...},...},
  "SnapFormat":{...}}]
```
`NetWork.Wifi`: см. §9.8. `NetWork.Nat`: `{"Addr":"secu100.net","NatEnable":true,"Port":8000,...}` (для отвязки от облака → `NatEnable:false`). `NetWork.PMS`: `{"Enable":true,"ServName":"push.umeye.cn",...}` (→ `Enable:false`).
`AVEnc.VideoWidget` (OSD): `[{"ChannelTitle":{"Name":"Camera1"},"ChannelTitleAttribute":{"RelativePos":[200,200,-1,-1],...},"Covers":[{...приватные маски, RelativePos [x0,y0,x1,y1] в 0..8192...}×4]}]`.
`Detect.MotionDetect`, `Alarm.PIR`, `Record`, `Storage.Snapshot` — массивы с `EventHandler{SnapEnable,RecordEnable,...}`, `TimeSection` (расписание строками `"1 00:00:00-24:00:00"`), сетки зон. `General.Location` — таймзона/DST. `Users` (см. §9.11). `SystemInfo` (MsgID 1020): HardWare, SerialNo, SoftWareVersion.

### 9.5 Живое видео — OPMonitor
1. **Claim:** MsgID **1413**, тело:
```json
{"Name":"OPMonitor","SessionID":"0x..","OPMonitor":{"Action":"Claim",
  "Parameter":{"Channel":0,"CombinMode":"NONE","StreamType":"Main","TransMode":"TCP"}}}
```
(`StreamType`: `"Main"` = 1080p, `"Extra"` = D1.) Ответ `Ret:100`.
2. **Start:** MsgID **1410**, то же тело с `"Action":"Start"`.
3. Далее в сокет **потоком идут медиа-пакеты**: каждый = 20-байт заголовок + payload. Payload — **DHAV-кадры** (§9.12). Демультиплексировать → H.264 (Annex-B) в MediaCodec, PCMA → AudioTrack.
4. **Stop:** MsgID 1410 с `"Action":"Stop"`. Держать поток = держать камеру бодрой.

### 9.6 Архив: список и проигрывание
**Список — OPFileQuery**, MsgID **1440**:
```json
{"Name":"OPFileQuery","SessionID":"0x..","OPFileQuery":{"BeginTime":"2026-09-01 00:00:00",
  "EndTime":"2026-09-30 23:59:59","Channel":0,"DriverTypeMask":"0x0000FFFF",
  "Event":"*","StreamType":"0x00000000","Type":"h264"}}
```
⚠️ **`"Event":"*"` обязателен** (иначе `Ret:119`). Ответ: `{"OPFileQuery":[{"BeginTime","EndTime","FileName","FileLength",...},...]}`.
Лимит ~**64** записи на ответ → пагинировать сужением интервала (напр. по 6-часовым окнам на день).
`FileName` = `/mnt/sd0/YYYY-MM-DD/001/HH.MM.SS-HH.MM.SS[A|R][@0][0](0).h264` (`[A]`=движение, `[R]`=обычная). `FileLength` — в КБ.

**Проигрывание/скачивание — OPPlayBack** (порядок опкодов ВАЖЕН):
1. **Claim:** MsgID **1424**:
```json
{"Name":"OPPlayBack","SessionID":"0x..","OPPlayBack":{"Action":"Claim",
  "StartTime":"<BeginTime>","EndTime":"<EndTime>",
  "Parameter":{"FileName":"<полный путь>","PlayMode":"ByName","StreamType":0,"Value":0,"TransMode":"TCP"}}}
```
2. **DownloadStart:** MsgID **1420**, то же тело с `"Action":"DownloadStart"`.
3. Читать медиа-пакеты (приходят с MsgID **1426**), payload = DHAV, **до пакета нулевой длины (EOF)**. Демукс → H.264 → декод/ремукс.
Скорость чтения с SD ~5 Мбит/с → проигрывать прогрессивно, буфер обгоняет реалтайм.

### 9.7 Двусторонний звук — OPTalk
1. **Claim:** MsgID **1434**: `{"Name":"OPTalk","SessionID":"0x..","OPTalk":{"Action":"Claim","AudioFormat":{"EncodeType":"G711_ALAW","BitRate":128,"SampleBit":16,"SampleRate":8000},"Channel":0}}`.
2. **Start:** MsgID **1430**, то же с `"Action":"Start"` — **без Start динамик не откроется**.
3. Микрофон телефона → PCM → кодировать в **G.711 A-law** → отправлять аудио-кадрами в сокет. `TalkAudioFormat` камеры: G711_ALAW/8000/16bit.

### 9.8 Wi-Fi настройка — SET NetWork.Wifi
GET/SET секции `NetWork.Wifi` (MsgID 1042/1040). Структура для подключения к сети:
```json
{"Enable":true,"SSID":"<имя_сети>","Keys":"<пароль>","Auth":"WPA2PSK","EncrypType":"AES",
 "KeyType":0,"NetType":"Infra","Channel":0,"WifiMode":true}
```
`Auth`: `OPEN`·`WEPAUTO`·`WPAPSK`·`WPA2PSK`·`WPANONE`. `EncrypType`: `NONE`·`WEP`·`TKIP`·`AES`·`TKIPAES`.
После записи камера переассоциируется и берёт новый IP по DHCP (аккуратно — уводит с текущей сети).
**SoftAP-онбординг:** после factory reset камера поднимает точку `xmTEXT` (WPA2, пароль `1234567890`; иногда открытая) или `camera_XXXX`; сама камера на `192.168.1.10`/`.12`, шлюз `192.168.1.1`. Подключить телефон к этой точке → DVRIP login → `SET NetWork.Wifi`. **Скан сетей камера не отдаёт** — SSID/пароль вводит пользователь.

### 9.9 Discovery (поиск камеры)
- **Пассивно:** камера периодически шлёт UDP-broadcast на порт **34569** — JSON `{"NetWork.NetCommon":{...HostIP/MAC/TCPPort/HttpPort...}}`. Слушать `0.0.0.0:34569`.
- **Активно:** отправить DVRIP-запрос на широковещательный `255.255.255.255:34569` (тело `{"Name":"NetWork.NetCommon","SessionID":"0x00000000"}`; опкод из семейства ~1530/OP-поиск — уточнить эмпирически), камеры отвечают своим NetCommon. Для v1 достаточно пассивного слушателя + добавление по IP.
- IP в NetCommon хранится hex-числом (напр. `HostIP:"0x1958A8C0"` = little-endian → `192.168.1.25`).

### 9.10 QR-онбординг (формат Xiongmai Wi-Fi QR)
QR содержит **плейнтекст**, строки через `\n` (только Wi-Fi, без облачного токена):
```
S:<ssid>
P:<пароль>
E:1                 // 1 = WPA2/PSK
M:<MAC роутера без двоеточий>
I:<последний октет IP роутера>
B:<случайный id>
```
Главное — `S` и `P`. Показывать сброшенной камере (режим сетапа) объективу. Генерить любой QR-библиотекой.

### 9.11 Пользователи / пароль
- **Список:** MsgID **1472** `{"Name":"Users"}` → массив аккаунтов (`Name`,`Group`,`AuthorityList[]`,`Password`(хэш)).
- **Переименование:** `ModifyUser` MsgID **1484**.
- **Смена пароля:** `ChangeRandomUser` MsgID **1660** (session-less). После смены проверять re-login.
- **Восстановление реального пароля:** `GetRandomUser` MsgID **1660** → поле `Info` (base64) расшифровать **AES-128-CBC, IV=0**, ключ = `SerialNo[5:11]+SerialNo[1:7]+SerialNo[8:12]` → строка `"p1:<user> p2:<pass> t:<token>"`. (У этой камеры пустого admin-бэкдора нет.)

### 9.12 DHAV-демукс (кадры потока → H.264/PCMA)
Медиа-payload состоит из кадров, начинающихся маркером `00 00 01 XX`:
- `XX = 0xFC` — видео I-кадр, `0xFD` — видео P-кадр, `0xFA` — аудио (G.711), и т.п.
- Внутри видео-кадров реальные H.264 NAL-юниты используют старт-код `00 00 00 01`.

**Проверенный практичный способ (видео):** пройти по всему буферу, найти все позиции `00 00 00 01`, извлечь NAL-сегменты между ними и склеить → получается корректный **Annex-B H.264** поток → в MediaCodec. (Xiongmai-заголовки `00 00 01 FC/FD` при этом отбрасываются/переносятся как хвост NAL и декодером терпимо игнорируются — этот способ подтверждён рабочим и на live, и на плейбэке.)
**Для корректной A/V-синхронизации и аудио:** парсить кадры по маркеру `00 00 01 XX` + длине (поле длины little-endian в заголовке кадра — уточнить смещение эмпирически на реальных данных): видео (FC/FD) → H.264, аудио (FA) → G.711 A-law 8кГц. Первый I-кадр несёт SPS/PPS (`00 00 00 01 67...`, `...68...`).

## 10. Обработка краевых случаев (обязательно)
- **Камера спит:** любой запрос → `timeout`/`No route to host`. UI: «спит, разбудите движением», фоновый probe, авто-подключение при пробуждении. Не спамить (интервал ~1–2 с).
- **IP сменился:** ловить по MAC через discovery; предложить статический lease.
- **Сессия протухла / камера уснула посреди операции:** переустановить сессию, повторить.
- **Медленный плейбэк с SD:** прогрессивная отдача, индикатор загрузки, не блокировать UI.
- **Неверные годы в архиве:** группировать по дате из имени файла, не по «сейчас».
- **Параллельные тяжёлые операции:** одна на камеру (live ИЛИ скачивание).
- **Нет RTSP/OPSNAP:** снапшот = кадр из декодера; никаких RTSP-URL.

## 11. Критерии приёмки (MVP)
1. Приложение находит камеру в сети (discovery) и/или добавляется по IP; логин проходит.
2. Live: после провокации движения камера ловится, показывается **реалтайм H.264-видео + звук**, поток удерживает камеру бодрой; снапшот и запись на телефон работают.
3. Архив: список записей грузится (с пагинацией и датами), запись **проигрывается с перемоткой** и скачивается в mp4.
4. Настройки: чтение и запись хотя бы кодека, OSD-имени, времени; смена Wi-Fi работает.
5. Несколько камер: список, переключение, независимые сессии.
6. Всё локально; нет обращений к облаку; креды в защищённом хранилище.

## 13. Распространение и самообновление с GitHub

Проект — **open-source на GitHub**, распространяется как подписанный APK (сайдлоад, не Play Store).
Требуется **встроенное обновление прямо из GitHub Releases**.

### 13.1 Схема самообновления (в приложении)
1. **Проверка версии:** `GET https://api.github.com/repos/<OWNER>/<REPO>/releases/latest`
   (публичный репо — без токена; unauth лимит 60 req/ч достаточно). Из ответа: `tag_name` (версия, семвер `vX.Y.Z`),
   `body` (чейнджлог, markdown), `assets[]` → нужный `.apk` (`assets[].browser_download_url`, `assets[].name`).
2. **Сравнение:** сравнить с `BuildConfig.VERSION_NAME`/`VERSION_CODE`. Хранить «последнюю показанную» версию, чтобы не надоедать.
3. **Скачивание:** качать APK по `browser_download_url` (редиректит на `objects.githubusercontent.com`) во внутренний кеш; прогресс; проверить размер/чексумму, если приложена.
4. **Установка:** через `PackageInstaller` (Session API): открыть сессию → записать байты APK → `commit()` → получить статус через `PendingIntent`. (Альтернатива — `Intent(ACTION_VIEW)` с `FileProvider` content-URI, MIME `application/vnd.android.package-archive`, `FLAG_GRANT_READ_URI_PERMISSION`.)

### 13.2 Обязательные условия (иначе обновление сломается)
- **Единый ключ подписи для ВСЕХ релизов.** Android обновит APK только если новый **подписан тем же keystore**, что установленный. → CI подписывает релиз **стабильным keystore из GitHub Secrets** (НЕ свежим debug-ключом на раннере). При смене ключа обновление невозможно (нужно удалять приложение).
- **Разрешение `REQUEST_INSTALL_PACKAGES`** в `AndroidManifest`. Перед установкой проверять `packageManager.canRequestPackageInstalls()`; если нет — вести пользователя в `Settings.ACTION_MANAGE_UNKNOWN_APP_SOURCES` для конкретного приложения.
- **Owner/Repo запиннить в коде** (не принимать произвольные источники). Только HTTPS (GitHub и так HTTPS).

### 13.3 CI/релизный пайплайн (GitHub Actions)
Workflow на пуш тега `v*`:
1. `setup-java` (JDK 17) → `./gradlew assembleRelease`.
2. **Подпись** релизного APK: keystore и пароли — в **GitHub Secrets** (keystore в base64 → декодировать в файл; `signingConfig` из env). Ключ **один и тот же** между релизами.
3. Прикрепить `app-release.apk` к GitHub Release (напр. `softprops/action-gh-release`), в теле релиза — чейнджлог.
- **Версионирование:** `versionName`/`versionCode` вывести из тега (напр. `versionCode` = число из семвера или счётчик коммитов), чтобы сравнение было монотонным.

### 13.4 UX обновления
- Настройки → «Проверить обновления» + опция **авто-проверки при запуске** (по умолчанию вкл, тихо).
- Диалог: текущая версия → новая, **чейнджлог** (`release.body`), кнопки «Обновить»/«Позже».
- Прогресс скачивания; после — системный диалог установки. Ссылка на репозиторий/релизы.

### 13.5 Альтернативы (упомянуть в README, не обязательно реализовывать)
- **Obtainium** — сторонний open-source апдейтер: пользователь добавляет URL репозитория, оно само следит за релизами и обновляет. Ноль кода в нашем приложении.
- **F-Droid** (свой или официальный репозиторий) — клиент F-Droid обновляет автоматически (больше настройки, требует воспроизводимой сборки для официального репо).

### 13.6 Критерии приёмки (самообновление)
- Приложение при запуске/по кнопке определяет наличие новой версии в GitHub Releases, показывает чейнджлог,
  качает и **устанавливает APK поверх** без удаления (подпись совпадает), данные сохраняются.
- CI по тегу собирает подписанный APK одним ключом и публикует в Release.
